# 文件夹级 AGENTS.md 创建

在目标文件夹内生成一个聚焦的 `AGENTS.md`。该文件为未来任何 agent（Claude Code、Codex 等）提供仓库根 `AGENTS.md` 未覆盖的、该文件夹特有的上下文。

## 流程

### 第一步：完整读取该文件夹内的每一个文件
- 先 `ls -la` 列出文件和子文件夹。
- **不要略读，不要跳过。** 用户后续的修改依赖于你已掌握完整上下文。

### 第二步：先起草一份候选内容的要点清单
在写文件之前，先给用户一份按章节分组的要点清单——让用户先反馈。候选章节（不适用的直接跳过）：

- **产品 / 目的**——这个文件夹/项目是什么、当前状态、关键指标
- **受众 / 用户画像**——它是给谁用的（如适用）
- **关键文件**——每个重要文件用一句话说明作用，包括跨文件夹引用（使用 `@相对路径/文件.md` 导入语法）
- **约束（MUST NOT）**——明确的硬性"禁止项"。这是文件里投入产出比最高的内容。
- **约定**——用户的术语、状态表情符号（✅ 🟡）、命名模式、"通常这样做"的模式
- **已锁定的决策**——已达成并注明日期的共识，不允许重新翻案
- **背景**——历史、权威性、为工作提供框架的可信度信息
- **如何与该用户协作**——针对这个具体文件夹的协作风格
- **营销角度 / 定位**——如果是面向公众的
- **核心洞察**——来自调研的 3–5 个最明显的信号（如果有调研的话）

### 第三步：与用户反复迭代
- 回答保持简短。用户会直接在 IDE 里改。
- 当用户修改文件后，**重新读取**并指出：矛盾、错别字、缺失的规则、归类错误。
- 除非用户要求，否则不要回退用户的修改。

### 第四步：写入文件
- 路径：`<folder>/AGENTS.md`
- 开头用一行标题说明该文件的用途。
- **子目录文件标记：**如果这是子目录文件（父文件夹已有自己的 AGENTS.md），则开头写：`先应用根目录 AGENTS.md，再应用本文件。`
- 使用与用户已认可章节对应的 `##` 标题。
- 多用要点，少用段落。要点要短。

## 规则

- **绝不编造内容。** 每一条要点都必须能追溯到你在文件夹里读到的东西或用户说过的话。不要通用套话。
- **简短至上。** 用户会大刀阔斧地改短。一开始就写紧凑。
- **只限文件夹范围。** 不要重复仓库根 `AGENTS.md` 的内容（人格、日期、端口等）。只写这个文件夹特有的东西。
- **不要文件树、不要目录罗列、不要代码本身就能看出的技术栈细节。** 任何 agent 用 `ls` 或 `grep` 就能推导出来的东西会很快腐化，而且浪费 token。要钉住的是决策、规则和上下文——不是结构。
- **约束 vs 约定。** 硬性"禁止"规则放"约束"（明确的否定项）。"通常做 X"的模式放"约定"。把这两类拆开能提高遵守率。
- **不要没有明确例外的绝对化 ALWAYS/NEVER。** 边界情况会让绝对规则被忽视。"绝不提交密钥——`.env.example` 除外" 比 "绝不提交密钥" 更好。
- **绝不总结或自动缩短文件。** 上下文坍缩会降低质量。要有意识地增长，手动修剪。如果用户要求精简，就手工来。
- **维护循环。** 当用户就某个本文件本应预防的事情纠正 agent 时，立刻把规则加进该文件。不要等。
- **诚实指出缺口。** 如果用户的修改引入了矛盾（例如某处说"卖 X"、另一处说"绝不卖 X"），在他开口前就指出来。
